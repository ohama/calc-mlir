# 문법 (Grammar)

Calc 언어의 어휘 구조, 구문, 의미를 정리한 문서입니다. 구현은 다음 파일에 있습니다.

| 단계 | 파일 |
|---|---|
| 어휘 (토큰) | `src/Calc/Lexer.fsl` |
| 구문 (파서) | `src/Calc/Parser.fsy` |
| AST | `src/Calc/Ast.fs` |
| 의미 (평가) | `src/Calc/Program.fs`의 `evalIn` |

## 1. 어휘 구조

### 토큰

| 토큰 | 패턴 | 예 |
|---|---|---|
| `NUMBER` | `[0-9]+` | `0`, `42` |
| `IDENT` | `[A-Za-z_][A-Za-z0-9_]*` (키워드 제외) | `x`, `foo_1`, `_tmp` |
| `LET` | `let` | |
| `IN` | `in` | |
| `EQUALS` | `=` | |
| `PLUS` `MINUS` `STAR` `SLASH` | `+` `-` `*` `/` | |
| `LPAREN` `RPAREN` | `(` `)` | |
| `EOF` | 입력의 끝 | |

### 규칙

- **공백**: 스페이스, 탭, 줄바꿈(`\n`, `\r\n`)은 토큰을 구분하는 역할만 하고 무시됩니다.
- **가장 긴 일치**: 렉서는 가장 길게 일치하는 패턴을 고릅니다. 길이가 같으면 `Lexer.fsl`에서 앞에 있는 규칙이 이깁니다.
  - `let`, `in`은 키워드입니다. 키워드 규칙이 `IDENT` 규칙보다 앞에 있기 때문입니다.
  - `letx`, `inner`는 `IDENT`입니다. 키워드보다 길게 일치하기 때문입니다.
  - `2x`는 `NUMBER 2`와 `IDENT x`로 나뉩니다.
- **대소문자 구분**: 키워드는 소문자만 인정합니다. `Let`은 `IDENT`입니다.
- **숫자 리터럴**: 음이 아닌 정수만 리터럴입니다. `-5`는 `MINUS`와 `NUMBER 5`로 나뉘고, 파서가 단항 마이너스로 처리합니다.
  - 32비트 `int` 범위를 넘는 리터럴(예: `2147483648`)은 렉서 단계에서 오류가 납니다.
- **그 밖의 문자**: 위 패턴에 맞지 않는 문자는 `Unexpected character: <문자>` 오류를 냅니다.
- **주석**: 아직 지원하지 않습니다.

## 2. 구문

### EBNF

```ebnf
program = expr EOF ;

expr    = NUMBER
        | IDENT
        | "let" IDENT "=" expr "in" expr
        | expr "+" expr
        | expr "-" expr
        | expr "*" expr
        | expr "/" expr
        | "-" expr
        | "(" expr ")" ;
```

이 문법은 그대로 두면 모호합니다. 아래의 우선순위와 결합 방향으로 모호함을 해소합니다. `Parser.fsy`도 같은 방식으로 작성되어 있으며 shift/reduce 충돌이 없습니다.

### 우선순위와 결합 방향

위에 있을수록 우선순위가 **낮습니다**. `Parser.fsy`의 선언 순서와 같습니다.

| 우선순위 | 연산자 | 결합 방향 | 선언 |
|---|---|---|---|
| 1 (가장 낮음) | `let ... in` | — | `%nonassoc IN` |
| 2 | `+` `-` (이항) | 왼쪽 | `%left PLUS MINUS` |
| 3 | `*` `/` | 왼쪽 | `%left STAR SLASH` |
| 4 (가장 높음) | `-` (단항) | — | `%nonassoc UMINUS` |

예:

| 입력 | 해석 |
|---|---|
| `2 + 3 * 4` | `2 + (3 * 4)` |
| `10 - 3 - 2` | `(10 - 3) - 2` |
| `8 / 4 / 2` | `(8 / 4) / 2` |
| `-5 + 2` | `(-5) + 2` |
| `2 * -3` | `2 * (-3)` |
| `1 - -2` | `1 - (-2)` |
| `--3` | `-(-3)` |

### `let` 식의 범위

`IN`의 우선순위가 가장 낮기 때문에 `let` 본문은 **오른쪽으로 갈 수 있는 데까지** 이어집니다.

| 입력 | 해석 |
|---|---|
| `let x = 1 in x + 2` | `let x = 1 in (x + 2)` |
| `1 + let x = 2 in x * 3` | `1 + (let x = 2 in (x * 3))` |
| `-let x = 1 in x + 2` | `-(let x = 1 in (x + 2))` |
| `(let x = 1 in x) + 10` | 괄호로 본문 범위를 제한 |

바인딩 값(`=`와 `in` 사이)에는 어떤 식이든 올 수 있습니다. 다른 `let`도 됩니다.

```
let x = let y = 2 in y * 3 in x + 1      // 7
```

## 3. AST 대응

| 구문 | AST (`Ast.Expr`) |
|---|---|
| `n` | `Number n` |
| `x` | `Var "x"` |
| `let x = e1 in e2` | `Let ("x", e1, e2)` |
| `e1 + e2` | `Add (e1, e2)` |
| `e1 - e2` | `Subtract (e1, e2)` |
| `e1 * e2` | `Multiply (e1, e2)` |
| `e1 / e2` | `Divide (e1, e2)` |
| `-e` | `Negate e` |
| `(e)` | `e` (괄호는 AST에 남지 않음) |

## 4. 의미 (평가 규칙)

평가는 환경 `env : Map<string, int>`에서 이루어집니다. 처음 환경은 비어 있습니다.

| 식 | 결과 |
|---|---|
| `Number n` | `n` |
| `Var x` | `env`에서 `x`의 값. 없으면 `Unbound variable: x` 오류 |
| `Let (x, e1, e2)` | `env`에서 `e1`을 평가해 `v`를 얻고, `env`에 `x = v`를 추가한 환경에서 `e2`를 평가 |
| `Add` / `Subtract` / `Multiply` | 왼쪽, 오른쪽 순서로 평가한 뒤 32비트 정수 연산 |
| `Divide` | 정수 나눗셈 (0 쪽으로 버림). 오른쪽이 0이면 `Attempted to divide by zero.` 오류 |
| `Negate e` | `-(e의 값)` |

### 성질

- **값은 32비트 정수(`int`) 하나뿐입니다.**
- **정수 나눗셈**: `7 / 2`는 `3`, `-7 / 2`는 `-3`입니다.
- **오버플로**: 검사하지 않고 값이 한 바퀴 돕니다. `2147483647 + 1`은 `-2147483648`입니다.
- **정적 범위**: 변수는 자신을 감싸는 `let`의 본문 안에서만 보입니다.
  - `(let x = 1 in x) + x`는 `Unbound variable: x` 오류입니다.
- **섀도잉**: 안쪽 `let`이 같은 이름을 다시 묶으면 본문 안에서는 안쪽 값이 쓰입니다. 본문을 벗어나면 바깥 값이 다시 보입니다.
  - `let x = 1 in (let x = 2 in x) + x`는 `2 + 1`이므로 `3`입니다.
- **재귀 없음**: 바인딩 값 `e1`은 바깥 환경에서 평가합니다. 그래서 `e1` 안에서는 자기 자신 `x`를 참조할 수 없습니다.
  - `let x = x + 1 in x`는 바깥에 `x`가 없으면 `Unbound variable: x` 오류입니다.

## 5. 오류

| 단계 | 원인 | 메시지 |
|---|---|---|
| 렉서 | 알 수 없는 문자 | `Unexpected character: <문자>` |
| 렉서 | `int` 범위를 넘는 숫자 | `Value was either too large or too small for an Int32.` |
| 파서 | 문법에 맞지 않는 토큰 나열 (예: `1 +`, `let x = 1`, `let in = 1 in 2`) | `parse error` |
| 평가 | 정의되지 않은 변수 | `Unbound variable: <이름>` |
| 평가 | 0으로 나누기 | `Attempted to divide by zero.` |

파서 오류 메시지에는 아직 위치(줄, 열) 정보가 없습니다.
